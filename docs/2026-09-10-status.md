# Visual Climate 현황과 다음 작업

확인일: 2026-09-10. 대상은 `pdf-45-50p-1-owid-climate/outputs/paris-movement`의
현재 작업 파일과 저장된 데이터다. 외부 원천의 최신 내용까지 재수집한 결과는 아니다.

## 이번에 고친 것

전부 `npm test` 43/43, `npm run engine:verify` 218/218, 프로덕션 워커
(`npm run build && npm start`) 실측으로 확인했다.

1. **프로덕션이 엔진에 연결되지 않던 문제.** 배포 빌드에는 `CLIMATE_API_BASE`가
   없어서 `/api/v1/country-dial`이 `lib/climate.ts`의 `countrySnapshot()`으로
   떨어졌다. 그것은 캄보디아 픽스처를 복제한 뒤 한국·브라질의 숫자 몇 개를
   손으로 덮어쓰고 나머지를 `unknown`으로 미는 함수였고, 배포본의 국가는 3개였다.
   - `countrySnapshot()`과 하드코딩된 3개국 목록을 삭제했다.
   - `scripts/stage-data.mjs`가 `data/countries/`와 새로 만든
     `data/engine-index.json`을 `public/data/`로 복사한다. `predev`·`prebuild`에 걸었다.
   - 라우트의 경로는 업스트림 → 정적 페이로드 두 가지뿐이다. 없는 국가는 404다.
   - 프로덕션에서 218개국, `X-Climate-Mode: static`으로 확인했다.
2. **이행 판정의 오류.** `derive.ts`는 목표가 최신 관측값보다 높으면 증가 추세와
   무관하게 `on_track: true`를 반환했다. 이제 관측 추세를 목표 연도까지 투영해
   그때도 목표 아래인지로 판정한다. 회귀 테스트를 넣었다.
3. **관측 연도 수 오계산.** `series.observed`는 소스마다 한 행이라 배열 길이는
   관측값 수이지 연도 수가 아니다. 한국은 75개 값 / 36개 연도다. 두 수를 분리했다.
4. **UI가 쓰던 고정 문장.** 화면의 평가 문장은 캄보디아 외 모든 국가에서
   `"Assessing delivery needs more observations."` 고정값이었다. 엔진이 218개국
   전부에 대해 필드 단위로 생성해 둔 `verdict.clauses`를 쓴다.
5. **빈 소스 레인.** 19개 영토에서 `emissions_profile.by_source`에 값이 하나도 없는
   소스 항목이 남아 차트에 빈 선을 그렸다. `compose.ts`에서 제거했다.
6. **골든 파일의 해시 불일치.** `data/golden`의 세 파일이 손으로 수정돼 자기
   `payload_sha256`과 맞지 않았다. 재빌드로 맞췄다.

## 이번에 추가한 것

`/country/<ISO3>` — 한 국가의 전체 레코드. 사양서 Part 6.1이 요구하는 7축 중
현재 데이터가 있는 축을 전부 화면에 올린다. 다이얼의 각 부품은 그 부품을 담은
섹션으로 링크된다 (`#emissions`, `#pledge`, `#transparency`, `#provenance` …).

| 섹션 | 데이터 | 커버리지 |
|---|---|---|
| 01 배출 | 소스별 시계열(병합하지 않음) · 가스별 · 섹터별 | 218 / 215 / 215 |
| 02 서약 | 파싱된 목표 · 등록부 현재 제출본 · CAIT 1차 라운드 평가 (셋을 분리) | 1 / 193 / 157 |
| 03 투명성 | BTR 8개 구성요소 | 0 확인 |
| 04 취약성 | ND-GAIN 지수·취약도·준비도 | 190 |
| 05 전망 | CMIP6 SSP1-2.6 ~ SSP5-8.5, 4개 시기 | 217 |
| 06 평가 | 필드별 생성 문장 전체 | 218 |

값이 없는 칸은 비운 채로 두고 없는 이유를 적는다. 바티칸은 5개 칸이 비고
각각 다른 이유가 붙는다.

## 남은 공백

218개는 국가·지역 레코드 수다. 모든 국가에서 모든 기능이 완성됐다는 뜻은 아니다.

| 항목 | 현재 | 의미 |
|---|---:|---|
| 목표 배출량 파싱 | 1 / 218 | 문서를 직접 읽은 것은 3건, 수치까지 나온 것은 캄보디아뿐 |
| BTR 구성요소 확인 | 0 / 1,744 | 218 × 8 전부 `unknown` |
| 수령 재원 금액 | 0 | 필요 재원과 수령액은 구분되어 있음 |
| 재해·재원 흐름·감축 잠재량·NAP·등급 | 확장 필드 없음 | 수집·소비 화면 모두 추가 필요 |
| 카탈로그 / 연결된 소스 | 42 / 11 | 정기 갱신 보장은 아님 |
| 운영 상태 | 파일 기반 엔진 | DB, 수집 스케줄, 실패 알림 미연결 |

사양서 Part 1.2의 차별화 기능 다섯 중 기능5(기후 전망)는 이제 화면에 있고,
기능1(NDC 격차)은 목표 파싱이 1개국이라 궤적만 그린다. 기능2·3·4는 데이터
수집 자체가 남아 있다.

## 다음 순서

1. **NDC 문서 파싱 (기능1을 살리는 유일한 길).** 사양서 패턴 D. `ndc_registry`에
   193개국의 문서 URL이 이미 있다. 한국·브라질부터 같은 파이프라인으로 수치를
   뽑고, 기준연도·BAU·가스·섹터 범위를 관측치와 비교 가능한지까지 기록한다.
   비교 가능성이 확인되지 않으면 추세만 내고 판정은 보류한다.
2. **BTR 8개 요소 추출.** 원문 섹션·페이지·첨부 파일명과 함께. 못 읽은 요소는
   미확인으로 남긴다. 미확인을 미제출·0원·실패로 바꾸지 않는다.
3. **기후 재원 수령액 (DS-GCF / OECD DAC).** 이것이 들어와야 사양서 기능3의
   취약성 × 재원 삼각 분석을 그릴 수 있다. 지금은 x축만 있고 y축이 없다.
4. **운영화.** 영속 저장소, 수집 주기, 실패 알림, 격리 레코드 검토.

소스 개수나 국가 수를 먼저 늘려도 위 공백은 줄지 않는다.
